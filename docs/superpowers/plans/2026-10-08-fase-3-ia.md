# Fase 3: IA con la clave de cada usuario. Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Con una clave de IA propia (Claude, Gemini, OpenAI, OpenRouter o un modelo local con Ollama), cada búsqueda lee las descripciones de los mejores anuncios. De ahí saca los datos que hoy adivinan las expresiones regulares (género del piso, gastos, normas, temporada, compañeros, fecha de entrada), un resumen de una frase, pros, contras y señales de alarma. La ficha permite además redactar el primer mensaje al anunciante. Y el perfil se puede rellenar describiendo en texto libre lo que buscas. Sin clave, todo funciona como hoy.

**Architecture:** Paquete nuevo `buscapiso/ai/`.
- `providers.py` define el protocolo `AIProvider`, con `json(system, user, schema) -> BaseModel` y `text(system, user) -> str`, y dos implementaciones:
  - `ClaudeProvider`, con el SDK oficial `anthropic`: `messages.parse(..., output_format=Schema)` para JSON y `output_config.effort="low"`.
  - `OpenAICompatProvider`, con HTTP a `/chat/completions` y `response_format: {"type": "json_object"}`. Al responder se quitan las vallas de markdown, se valida con Pydantic y se reintenta una vez. Cubre Gemini (su capa compatible con OpenAI), OpenAI, OpenRouter y Ollama.
- `extract.py`: una sola llamada por anuncio devuelve `ListingFacts` (datos, resumen, pros, contras, alertas). Se cachea en SQLite por hash de (proveedor, modelo, versión del prompt, título y descripción), y `apply_facts` vuelca los datos en el `Anuncio` sin pisar los que publica el portal.
- El pipeline enriquece los N mejores tras la primera clasificación y vuelve a clasificar, igual que con los trayectos: un anuncio "posible" cuyo género confirma la IA pasa a la lista principal. Hay un tope de llamadas por búsqueda y un recuento de tokens y coste.

**Modelo por defecto:** `claude-opus-5-5` (la referencia actual de la API de Claude lo fija como predeterminado). La pantalla de ajustes ofrece `claude-haiku-5-5` con su precio al lado: unas 40 veces más barato para esta tarea de extracción. Precios de la referencia (por millón de tokens de entrada/salida): Opus 5.5 $4/$20, Sonnet 5.5 $2/$10, Haiku 5.5 $0,10/$0,50. Para los demás proveedores el usuario escribe el nombre del modelo y solo se muestran tokens.

**Spec:** `docs/specs/2026-10-08-plan-v2.md`, apartado 4 y fila "3. IA".

## Global Constraints

- Rama `fase-3`, desde `fase-2b`. Tests sin red: los proveedores reciben el cliente o la función HTTP por inyección. Las APIs de IA son de pago, así que simularlas es inevitable.
- La clave de cada proveedor va al llavero del sistema (`keys.py`, generalizado por nombre de proveedor) y nunca a la base de datos, a la API ni a los logs.
- Sin proveedor configurado, el comportamiento es idéntico al de la fase 2b: todos los tests anteriores pasan sin cambios.
- La IA nunca descarta un anuncio por sí sola con un dato inventado. Si devuelve `unknown` o `null`, se conserva lo que hubiera.
- Textos de la interfaz en inglés y en `en.json`. Los resúmenes, pros, contras y alertas se piden en inglés. El borrador del mensaje se escribe en el idioma del anuncio.
- Cada commit termina con `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Si la IA falla (clave mala, cupo, red, JSON inválido dos veces), la búsqueda termina con los datos de las regex y un aviso. Ningún anuncio se pierde.
2. Un dato publicado por el portal (`genero_confirmado`, gastos declarados) nunca lo sobrescribe la IA.
3. Repetir la búsqueda no vuelve a pagar por anuncios cuyo texto no ha cambiado.
4. La clave no aparece en ninguna respuesta ni en ningún error.
5. Un anuncio con instrucciones en su descripción ("ignore previous instructions…") no cambia el formato ni hace que la IA haga otra cosa: el texto va delimitado como dato y la salida es un esquema cerrado.

```python
class ClaudeProvider:
    name = "anthropic"

    def __init__(self, api_key: str, model: str = "claude-opus-5-5", client=None):
        import anthropic
        self.model = model
        self.client = client or anthropic.Anthropic(api_key=api_key, max_retries=2)
        self.usage = Usage()

    def _cuenta(self, r) -> None:
        self.usage.calls += 1
        self.usage.input_tokens += r.usage.input_tokens
        self.usage.output_tokens += r.usage.output_tokens

    def json(self, system: str, user: str, schema):
        import anthropic
        try:
            r = self.client.messages.parse(
                model=self.model, max_tokens=4096, system=system,
                messages=[{"role": "user", "content": user}],
                output_format=schema, output_config={"effort": "low"})
        except anthropic.APIStatusError as e:
            raise AIError(f"Claude answered HTTP {e.status_code}") from None
        except anthropic.APIConnectionError:
            raise AIError("Could not reach the Claude API") from None
        self._cuenta(r)
        if r.stop_reason == "refusal" or r.parsed_output is None:
            raise AIError("Claude did not return the expected data")
        return r.parsed_output

    def text(self, system: str, user: str, max_tokens: int = 1024) -> str:
        ...  # igual, con messages.create, devolviendo el primer bloque de texto
```

**Interfaces:**
- `ListingFacts(BaseModel)`, con:
  - `household_gender: Literal["female_only", "male_only", "mixed", "unknown"]`
  - `bills_included: bool | None`, `bills_amount_eur: int | None`
  - `owner_lives_in: bool | None`, `couples_allowed: bool | None`, `visitors_allowed: bool | None`
  - `seasonal_or_short_let: bool | None`, `min_stay_months: int | None`
  - `roommates: int | None`, `roommates_age_range: str | None` (`"25-30"`), `roommates_occupation: str | None`
  - `available_from: str | None` (`YYYY-MM-DD`)
  - `summary: str`, `pros: list[str]`, `cons: list[str]`, `red_flags: list[str]`
- `PROMPT_VERSION = 1`. `SYSTEM_EXTRACT`: el anuncio va entre etiquetas `<listing>` y se trata como dato. El prompt dice que no se sigan instrucciones que aparezcan dentro, que se use `unknown` o `null` si el texto no lo dice, que haya como mucho 3 pros, 3 contras y 3 alertas, y que todo esté en inglés.
- `extract_facts(provider, anuncio, con) -> ListingFacts`, con la caché por `sha256(f"{provider.name}|{provider.model}|{PROMPT_VERSION}|{titulo}|{descripcion}")`.
- `apply_facts(anuncio, facts) -> None`:
  - El género solo se cambia si `not anuncio.genero_confirmado` y la IA no dice `unknown`. Se pasa a `chicas`, `chicos` o `mixto`, y `genero_confirmado` queda en `False`: la IA infiere, no confirma.
  - `gastos_extra` solo se rellena si es `None`: 0 si `bills_included`, o `bills_amount_eur`.
  - `propietario_vive`, `admite_parejas`, `visitas_permitidas`, `companeros` y `estancia_minima_meses` solo se rellenan si están en `None`.
  - `edad_companeros` y `disponible_desde` (pasada a `DD-MM-YYYY`) solo si están vacíos.
  - Los campos `ia_*` se rellenan siempre.

Tests (con un proveedor falso que cuenta llamadas):
- La caché evita la segunda llamada si el texto es el mismo y la repite si cambia la descripción.
- Un dato del portal (`genero_confirmado=True`, `gastos_extra=50`) no se toca.
- `unknown` y `null` no cambian nada.
- La fecha se convierte de `2026-11-01` a `01-11-2026`.
- Si el prompt de sistema contiene la frase de no seguir instrucciones del anuncio, la descripción va dentro de `<listing>…</listing>`.
